### Задание 1. Запуск модульных тестов для проекта

Запустить проект прошлого года из своей ветки:

Запустите виртуальный сервер XAMPP (кнопка Apache и mySQL)  
Работайте в GitBash - перейдите в папку `/c/xampp/htdocs/pizza221` (или клонируйте репозиторий `https://github.com/Coopteh/pizza221`)  
Перейдите в папку `pizza221` и переключитесь на ветку `my_branch`  
Выполните все зависимости проекта, запустив менеджер зависимостей `composer install`  
Проверьте запустился ли сайт по `localhost` (в браузере)   
Создайте (в корне сайта) файл `.gitignore` в который строку `vendor/` (добавит папку как игнорируемый путь для git)  
Теперь добавьте новые и измененные файлы в локальный репозиторий командой `git add *`,   
зафиксируйте изменения `git commit -m "Добавлен файл .gitignore"`  
Сайт запускается и работает!

### Задание 2. Создание пайплайна

Выполните тесты командой `vendor/bin/phpunit ./tests --color`  
Если тесты в папке `test` успешно выполняются - можете продолжать (иначе - обратитесь к преподавателю)  

В корне сайта создайте папку `.github`, перейдите в нее и создайте еще подпапку `workflows` (должно получиться `.github/workflows`)  
Перейдите в `.github/workflows` и создайте файл `<название вашей ветки>-deploy.yml`, добавив в него следующее содержание  
```
name: PHP_CI_<название вашей ветки>

on:
  push:
    branches:
      - <название вашей ветки>

jobs:
  build:
    runs-on: ubuntu-latest

    steps:
      - name: Checkout code
        uses: actions/checkout@v2

      - name: Setup PHP
        uses: shivammathur/setup-php@v2
        with:
          php-version: '8.2'

      - name: Install dependencies
        run: composer install

      - name: Run PHPUnit tests
        run: ./vendor/bin/phpunit tests
```
В секции `on` измените название ветки на свою `<название вашей ветки>`  
(чтобы триггерить выполнение пайплайна на событие пуша в свою ветку на гитхабе)  
Вы создали пайплайн для CI на GitHub Actions, поздравляем!  

Теперь надо проверить, что он работает:
```
Работать в своей ветке.
Теперь добавьте новые и измененные файлы в локальный репозиторий командой git add *
зафиксируйте изменения git commit -m "Добавлен пайплайн"
передайте изменения на удаленный репозиторий командой git push

проверьте на странице GitHub Action появление своего пайплайна (название слева) PHP_CI_<название вашей ветки>
измените тесты так, чтобы они срабатывали неверно - добавьте изменения в индекс, закоммитьте и запуште.
проверьте что тесты непроходят на GitHub Action
измените тесты так, чтобы они проходили
проверьте что тесты проходят на GitHub Action
```
Вы проверили работу автотестов через CI процесс на GitHub Actions, поздравляем!
